Frontend Design System

Guía de Diseño Frontend

Estándar visual para mantener una interfaz consistente, minimalista y acogedora en Casa Del Valle. Esta guía define colores, tipografía, espaciado, componentes, formularios, navegación y reglas de uso.

Minimalista Reducir elementos innecesarios y priorizar el contenido.
Acogedor Usar tonos cálidos, espacios generosos y formas suaves.
Consistente Los mismos patrones deben repetirse en toda la aplicación.
01 — Identidad visual

La personalidad de Casa Del Valle

La interfaz debe transmitir una sensación de hogar, confianza, tranquilidad y sencillez. El diseño no debe sentirse tecnológico o agresivo; debe sentirse cercano.

Calidez

El fondo crema y el marrón deben aportar una sensación natural y confortable.

Naturalidad

El verde funciona como color institucional y debe aparecer principalmente en navegación, elementos secundarios y estados.

Énfasis

El naranja es el color de acción. Debe utilizarse con moderación para llamar la atención sobre acciones importantes.

02 — Color

Paleta oficial

Estos cinco colores forman la identidad visual principal. No se deben introducir colores arbitrarios sin una razón de diseño.

Verde Valle #4F5D2F
Marrón Tierra #423629
Naranja Acción #EC4E20
Crema #EFE6D2
Negro #151515
Verde #4F5D2F: navegación, encabezados institucionales, botones secundarios, estados positivos y elementos de identidad.
Marrón #423629: títulos, footer, bloques de código y elementos que necesiten una apariencia más cálida.
Naranja #EC4E20: acciones principales, botones CTA, indicadores de atención y estados de error.
Regla: El naranja es un color de énfasis. Evitar utilizarlo como color dominante de toda una página.
03 — Tipografía

Serif para identidad, Sans para claridad

La combinación de Serif y Sans-serif permite mantener una personalidad clásica en los títulos sin sacrificar legibilidad en formularios y contenido.

Serif — Títulos

Casa Del Valle
La tipografía Serif se utiliza en títulos, nombre de marca y encabezados importantes.
Georgia / Times New Roman
  • H1: 2rem — 3.5rem
  • H2: 1.6rem — 2.2rem
  • H3: alrededor de 1.35rem
  • Evitar utilizar Serif en bloques largos de texto.

Sans-serif — Contenido

Los formularios, botones, navegación, párrafos, mensajes y datos deben utilizar una tipografía Sans-serif limpia.
Arial / Helvetica
  • Texto base: 15–16px.
  • Labels: 14–15px.
  • Botones: 14–15px.
  • Line-height recomendado: 1.5–1.7.

05 — Superficies

Bordes, sombras y esquinas

Los componentes deben sentirse suaves y discretos. Las sombras sirven para separar superficies, no para decorar.

Border radius

Usar 6px para controles pequeños, 10px para componentes y hasta 16px para contenedores grandes.

Sombras

Utilizar sombras suaves y difusas. Evitar sombras negras fuertes alrededor de cada elemento.

Bordes

Preferir bordes sutiles en tonos marrones claros antes que líneas negras gruesas.

06 — Componentes

Componentes principales

Los componentes deben conservar el mismo lenguaje visual independientemente de la página donde aparezcan.

Botones

Acción principal Acción secundaria Cancelar

Uso

  • Naranja: acción principal de la pantalla.
  • Verde: acción secundaria o institucional.
  • Outline: acciones de menor prioridad.
  • No utilizar cinco botones con el mismo nivel de importancia.

Formularios

Usar instrucciones cortas cuando sean necesarias.

Reglas de formularios

  • Labels siempre visibles.
  • Campos con altura suficiente para interacción cómoda.
  • Placeholder no sustituye al label.
  • Mostrar claramente estados de error y éxito.
  • Utilizar el mismo estilo de input en toda la aplicación.
07 — Navegación

Header y navegación

La navegación debe ser simple. El usuario debe poder identificar rápidamente dónde está y a dónde puede ir.

Casa Del Valle
Inicio Ingresar

Reglas

  • Fondo principal: #4F5D2F.
  • Texto de navegación: blanco.
  • Logo o nombre: Serif.
  • Enlaces: Sans-serif.
  • Evitar llenar el header con demasiadas opciones.
  • En móvil, reorganizar los enlaces en lugar de reducirlos excesivamente.

09 — Estados

Mensajes y estados de la interfaz

Los estados deben ser visibles sin romper la estética general. No introducir colores completamente nuevos para cada situación.

Éxito: Los cambios se guardaron correctamente.
Información: Puedes modificar estos datos más adelante.
Advertencia: Esta acción puede afectar otros datos.
Error: No fue posible completar la operación.

Regla importante

Los estados deben apoyarse también en texto o iconografía. Nunca depender únicamente del color para comunicar un error, éxito o advertencia.

10 — Responsive

Diseñar primero para contenido

El diseño debe funcionar correctamente en escritorio, tablet y móvil sin perder la identidad visual.

Desktop

Aprovechar el espacio mediante contenedores centrados. Evitar líneas de texto excesivamente largas.

Tablet

Reducir columnas y mantener suficiente espacio entre elementos interactivos.

Móvil

Convertir grids en una sola columna y permitir que la navegación se reorganice naturalmente.

Regla: Nunca diseñar una interfaz únicamente para la resolución de la computadora del desarrollador.
11 — Accesibilidad

Minimalista también significa usable

Una interfaz bonita no sirve si una persona no puede utilizarla correctamente.

Todos los inputs tienen un label.
Los botones tienen texto comprensible.
El teclado puede recorrer los elementos interactivos.
Los estados de error no dependen únicamente del color.
El texto tiene suficiente contraste con el fondo.
Las imágenes importantes tienen texto alternativo.
Los elementos interactivos tienen un área cómoda para pulsar.
Se respeta la preferencia de reducir movimiento cuando corresponde.
12 — Reglas de diseño

Qué hacer y qué evitar

✓ Sí hacer

  • Usar la paleta oficial.
  • Mantener bastante espacio en blanco.
  • Usar Serif en títulos y Sans-serif en contenido.
  • Reutilizar componentes existentes.
  • Utilizar naranja para acciones importantes.
  • Mantener formularios simples.
  • Diseñar pensando en móvil.
  • Mantener consistencia entre páginas.

✕ Evitar

  • Introducir colores arbitrarios.
  • Usar demasiadas sombras.
  • Utilizar gradientes llamativos.
  • Hacer botones gigantes sin necesidad.
  • Llenar una pantalla con tarjetas.
  • Usar Serif para párrafos largos.
  • Ocultar labels dentro de placeholders.
  • Crear estilos diferentes para cada página.
13 — Implementación

Variables CSS obligatorias

Los colores y medidas principales deben centralizarse mediante variables para evitar valores duplicados. 

:root {
    --green: #4F5D2F;
    --brown: #423629;
    --orange: #EC4E20;
    --cream: #EFE6D2;
    --black: #151515;

    --radius-sm: 6px;
    --radius-md: 10px;
    --radius-lg: 16px;

    --space-1: 4px;
    --space-2: 8px;
    --space-3: 12px;
    --space-4: 16px;
    --space-5: 24px;
    --space-6: 32px;
    --space-7: 48px;
    --space-8: 64px;
}
Regla: Si necesitas cambiar un color institucional, debe cambiarse desde las variables globales y no modificando cientos de componentes.

15 — Checklist

Antes de aprobar una pantalla

El equipo frontend puede utilizar esta lista durante las Pull Requests y revisiones de diseño.

¿Utiliza únicamente la paleta definida?
¿Los títulos utilizan Serif?
¿El contenido y formularios utilizan Sans-serif?
¿Existe suficiente espacio entre elementos?
¿Los botones respetan los colores y jerarquía?
¿Los formularios tienen labels visibles?
¿La pantalla funciona en móvil?
¿Los estados de error y éxito son claros?
¿Los componentes reutilizan estilos existentes?
¿La pantalla se siente parte de Casa Del Valle?
Principio final

Diseñar menos, pero diseñarlo bien.

Cada pantalla debe sentirse como parte del mismo producto. Si un componente nuevo necesita demasiados colores, sombras, tamaños o excepciones para funcionar, probablemente el diseño puede simplificarse.
